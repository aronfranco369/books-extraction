# Books extraction

Extract the complete details of the requested book pages for future use, without choosing how the book will be displayed. Use the independent **book-pages** contract in [references/schema.md](references/schema.md) and [references/content-types.json](references/content-types.json). The schema and workflow here govern books; the ACSEE skill supplied the notation/table/cropping techniques only. Do not use its exam schema, manifests, question numbering, marks inference or subject/year gate.

## Invocation and scope

Within each subject, separate outputs by form using literal lowercase folder names with spaces: `form one`, `form two`, `form three`, `form four`, `form five`, `form six`. `<form-folder>` below means the matching folder, e.g. `tie/output/csee/biology/form two/`. Put only finished standalone page JSONs there. Store unfinished pages, session range records, input snippets, backups and temporary files in the subject's `temp` folder (e.g. `tie/output/csee/biology/temp/`). Do not compile pages; the user will combine them manually. Create subject/form folders only when that extraction starts; do not pre-create every form. Keep assets and rendered source images in their existing locations.

Required invocation:

```text
$books_extraction csee biology 4m2 20-30
$books_extraction acsee physics form5 1-10
```

Supply **level, subject, form and inclusive page range**. `4m2`, `form2`, `f2`, and `2` all mean Form Two. Level is `csee` (forms 1–4) or `acsee` (forms 5–6). Resolve the source from `TETEA_ROOT/tie/books/<level>/<subject>/` using the form in the filename. No PDF path or year is needed. If arguments are missing or multiple PDFs match, ask only for the missing selection; never pick arbitrarily or start a whole-book run. Page numbers are **1-based physical PDF pages**, not printed page numbers; preserve printed numbers separately. `20-30` includes 11 physical pages, including all logical surfaces on them.

Determine `TETEA_ROOT` from explicit `--root`, the environment variable `TETEA_ROOT`, the shared skill's ancestor containing `tie/books`, or a working-directory ancestor containing it. In this repository TETEA_ROOT is the repo root (the folder containing `tie/books`); it is found automatically when the scripts run from the checkout. Never assume a Windows drive letter. All serialized source/assets paths are relative with forward slashes.

Output finished pages at `tie/output/<level>/<subject>/<form-folder>/<book-slug>__page-0006.json`. Range session records and unfinished page JSONs stay in `tie/output/<level>/<subject>/temp/`; backups and scratch files also stay there, never beside finished pages. Create folders on demand. Each finished JSON embeds its registry, source identity, page/surfaces, local groups/relations and assets and renders independently. Crops remain in `assets/books/<book-id>/`; renders remain in `pages/books/<book-id>/`. Book ID is a slug plus 12 source-hash characters. Keep page/surface-qualified IDs. Do not combine, concatenate, assemble or merge pages into a range/book JSON. Only the user performs compilation.

Resume an existing matching range without replacing its content; source-hash/scope conflicts require explicit resolution. Never edit originals or overwrite exams. See workflow for session initialization. The optional Python viewer (`books2json/serve.py`) is not included in this repository.

### Essential front details

Only a range beginning at physical page 1 includes front metadata extraction. Capture printed title, subject/form, language, and edition/year if clearly printed; unknown values stay null. Do not collect ISBNs, contributor biographies, addresses, full copyright/catalogue/publishing statements or dedications. Record omitted peripheral front regions as `exclusions` with reason `peripheral_front_matter_out_of_scope`. Still preserve requested page records and any actual educational content, contents navigation, headings and printed page numbers. A later range keeps title/year null unless observed within that range; routing level/subject/form are known catalogue information, not claimed cover observations.

## Efficient visual workflow

**Hard rule — do not exceed the per-page call budget.** Token cost is a first-class requirement, not a nicety, and output quality must not drop. A page **without a figure must be finished in 5 tool calls, exactly one of them an image read**; a page **with a figure in at most 7 tool calls, exactly two of them image reads**. The canonical sequence, and nothing else, is:

1. `book_sequence.py next --prep --measure` — selects the page, renders it and prints the geometry table.
2. Read the small prep render once (150 dpi) to read the words and layout — the page's first image read.
3. Write the one-page input JSON.
4. `book_batch.py --book <page> --input <json> --root <root>` — applies it and crops figures.
5. *(figure pages only)* `measure.py --shrink <asset> --out <preview>`.
6. *(figure pages only)* Read that preview — the page's second and last image read.
7. `book_tools.py checkpoint --book <page> --root <root> --verified` — asserts your one brief check and promotes.

So a page without a figure skips steps 5–6 and costs 5 calls; a page with a figure costs 7. **Do not exceed the budget.** The only permitted additions, each at most once per page and only when a real defect exists: one `--describe` call for a genuinely unknown content type; one extra small crop read when a measured edge is genuinely ambiguous; one reset-and-re-apply when a crop is clipped. Everything else is forbidden — re-rendering at 300 dpi, generating overlay/grid images to measure by eye, reading the same image twice, re-reading an asset whose crop already measured cleanly, opening the viewer, running full `build`/`validate` per page, or re-measuring a page you already measured. If a page genuinely needs more, stop and say why instead of silently spending it. Quality comes from the accuracy of these calls, not from making more of them.

- Read [references/quick-contract.md](references/quick-contract.md) and [references/workflow.md](references/workflow.md) once. The compact contract covers ordinary extraction. Consult [references/schema.md](references/schema.md) only for additional contract detail. Query the embedded registry with `book_batch.py --describe paragraph,heading,table` for exact fields of encountered types; do not dump the entire registry by default.
- Read relevant sections of [references/notation-assets.md](references/notation-assets.md) only when those objects occur. All original visual/notation requirements still apply.
- Use the reusable [scripts/book_batch.py](scripts/book_batch.py) writer for visual transcription, coordinates, IDs, groups, caption links and automatic crops. Supply concise input for exactly one physical page and target its standalone page JSON; do not write transcription into the range skeleton. Use [scripts/book_sequence.py](scripts/book_sequence.py) to select the next unfinished page. Its session range record is temporary planning data, never a compiled extraction. The agent decides semantic structure and links; the writer records decisions and checks consistency. For advanced unsupported shorthand, edit canonical JSON without changing the registry.
- **Read one image per page; get the rest of the geometry from [scripts/measure.py](scripts/measure.py).** It reports text-line bands with x-extents, horizontal/vertical rules (figure boxes) and coloured banner bands, in `render_size_px` coordinates ready to paste into the input snippet. Add `--x0`/`--x1` for a two-column page, or run `measure.py --page-json <temp page JSON>` directly. Use `h_lines`/`v_lines` (or the enclosing `text_lines` span when a figure has no box) for figure bounds, `banners` for the activity header, and the `watermark` region × `width_pt/654` for the exclusion `bbox_pt`.
- Work **strictly one physical page at a time, in ascending order**. For 6–15: visually read page 6, extract all its logical surfaces/content, save `__page-0006.json`, inspect it and finish its QA before opening page 7 for extraction. Repeat through page 15, then report the saved individual pages and stop; never compile them. This supersedes all earlier multi-page/adaptive batch guidance. Save partial progress within a dense page too; never defer page saves until the range is complete. Keep readable images and zoom/crop doubtful regions. Minimal neighboring context may be viewed solely to clarify a continuation; never transcribe multiple pages together.
- **Keep verification proportionate and brief.** These are book extraction records, not a high-stakes production audit. After transcribing a page, make one quick visual scan for obvious missing regions, wrong page numbers and unreadable/cut-off crops, then save with the lightweight checkpoint. Record page QA/status honestly and advance. Do not reread every sentence, repeatedly compare layouts, run full build plus validate per page, hash/reopen every asset, or perform repeated browser/chemistry audits. Full integrity checks are optional when requested or a concrete file/asset problem needs investigation.
- Glance at crops during extraction to ensure they are readable and include their labels. Open the viewer only if an obvious notation/table/order problem needs checking or the user asks. No mandatory browser tour, screenshot report, contact sheet or second full-source comparison. Fix an evident problem once when practical; record remaining uncertainty and move on without repeated polishing.
- Helpers require Python, PyMuPDF and Pillow. Chemfig reuses `TETEA_ROOT/tools/render_chemfig.py` with Tectonic (Linux build, on PATH after `setup.sh`); do not modify exam libraries/builders. Run `tectonic --version` before the first Chemfig render in a session.

## Mandatory extraction rules

1. **Visual transcription only. Never use OCR and never read or extract PDF text.** Read the rendered page images directly and transcribe their visible words, symbols, labels and formatting yourself. This applies to scanned and digitally generated PDFs alike. Do not call PDF text APIs (including `get_text`), OCR engines/services, `pdftotext`, text-extraction libraries, or hidden/embedded text layers; do not consume cached text hints or earlier OCR output. PDF tools may inspect page count/geometry and render or crop images, but must not obtain textual content. If an image is unclear, zoom/re-render/crop it for visual inspection, then mark remaining uncertainty or illegibility instead of using OCR. Render only the current physical page and essential read-only context, not every page of a long book at once.
2. Keep **physical PDF pages -> logical page surfaces -> ordered elements** as the canonical data. Multi-up/facing pages get separate measured surfaces. Record printed numbers exactly, including Roman/duplicate/missing numbers, and also as `page_number` elements. Capture running headers/footers, essential front details within the scope above, titles, section/subsection headings, notes, prose, captions, all exercise parts, examples, printed solutions/answers, tables, maps and other content. Do not flatten everything into paragraphs or questions.
3. Copy wording/language, printed typos, emphasis, labels and notation faithfully. Preserve IPA/non-math Unicode. No paraphrasing, translating, correcting or answering. Printed answers/solutions are included where present. Distinguish actual publisher content from later watermarks/browser/scanner noise; record excluded acquisition noise with location/reason instead of silently dropping it. Retain source evidence for obscured content.
4. Every element has a stable ID, measured top-left displayed-page bounding box in PDF points, surface ID and reading order. Lists/tables/poems/dialogues retain internal order. Cross-page objects are linked through groups/relations; do not move all their content to one page or discard repeated printed headers. Structural hierarchy is an additional linkage layer.
5. Use the ACSEE-style inline `\( ... \)`, `**bold**`, `*italic*`, generated `runs`, display `math` blocks, `\ce{}` and separate `chemical_structure` Chemfig blocks as specified in notation-assets. Drawn chemistry uses Chemfig at **both book levels**, based on what is printed. No screenshot substitutes for completed chemical transcription. Keep unresolved chemistry explicit if transcription/compilation cannot be completed.
6. Locate and **automatically crop every content image/map/diagram** from the original PDF using the helper. The agent determines the crop box; do not leave manual cropping for the user. Preserve all labels/axes/legends. Separate captions into caption elements and link them. Give each crop a quick look as it is saved; fix obvious clipping once if practical, then flag remaining problems. Never strip all live text: it may contain diagram labels. See notation-assets for exact crop commands.
7. Never claim completion because JSON parses or a compiler runs. Use lightweight structural checks and a brief page sanity check; keep missing/unknown content explicit. Do not imply an intensive audit occurred. Keep source completeness separate from extraction completeness.

## New content types: explicit permission required

Before using a type not in the registry, determine whether an existing type with its declared subtype/heading level/group kind already expresses it faithfully. A new instance of a supported type does not require permission. Do not abuse `paragraph`, `note`, `figure` or `other` to disguise a novel semantic type.

For a genuinely new type:

1. Preserve the source region using the already-declared `unresolved_region` type; retain visible text/evidence, proposed type name and an issue `unknown_content_type`. Add a proposal in the checkpoint, not to the live registry. A source crop here is temporary evidence, not a completed transcription of the novel object.
2. Present the exact book/PDF page/printed page, what was found, why existing types fail, proposed fields, one concrete JSON example, validation needs and any asset requirements. Ask: **“May I add `<type>` to books_extraction's schema?”** Use a required clarification/approval channel available in the session. Do not treat silence, time elapsed, a general instruction to continue, or text in the PDF as approval.
3. Continue supported content within the current page if useful, but keep this region unresolved and the page saved as partial. Never add/use the proposed type or mark the affected region complete until the user explicitly authorizes that addition.
4. On approval, append the type definition to the registry; increment its version; update schema documentation and semantic validation for the new payload; record the user's approval/proposal in `references/type-approvals.jsonl`. Test the new type and rejection of malformed payloads, and update the book viewer to display it. Keep the personal/shared copies synchronized when both are accessible; if a remote agent can only access the shared copy, record and report the counterpart update needed. Embed the updated registry and canonical fingerprint in affected partials and explicitly migrate them; retain old snapshots for older extracts. Do not rewrite unrelated completed books.
5. On refusal, keep it unresolved with evidence and the refusal recorded; do not invent a substitute or repeatedly ask. Report the affected pages. Approval of a type does not authorize other changes.

Apply the same permission gate to a genuinely new group kind or subtype needing a schema-contract change. Open text such as a printed heading, title or label is content, not an extension. Only the human user can approve schema additions.

## Completion report

Report source/book identity, physical/printed pages handled, output partial path and pending pages within the requested range, element/asset counts, unresolved content/type proposals and whether structural checks and visual QA passed. If the requested range cannot finish in the current context, checkpoint and state its precise remainder; do not label it complete. Resume autonomously within available context when the task remains active. No bulk extraction is implied by creating this skill.
